# Notes pipeline throughput research and implementation

## Decision

Keep the staged Node/SQLite/OpenCode/TiDB pipeline, complete official transcripts, the written-shiur contract, Muse High, teacher priority, and hash-verified publication. Implement measurable waste reduction and recovery safeguards before increasing load. The user's ceiling is six simultaneous AI sessions. Fetchers and publishers do not run inference.

The attached RESEARCH.md was checked against the working tree and the installed VM. The initial read-only snapshot found 1,168 completed replacements, 49 ready sources, and one generation request active at that instant. Over its preceding hour, 51 publications were verified; 15 generation requests ended `server_unavailable`. Memory admission repeatedly closed. Available host memory initially measured about 2.6 GiB and later recovered above 6 GiB, showing why a one-time headroom sample cannot justify permanent scaling. These are mixed-workload observations, not a controlled baseline or a corpus ETA. Private baseline evidence is `outputs/notes-throughput/baseline.json`.

## Implemented choices

1. **Enforce six at every admission surface.** The CLI, pool file validator, coordinator, shared inference limiter, server adapter, qualification records, and qualification runner reject larger settings. Pending session creations count before their IDs arrive. A lost session-creation acknowledgement pauses the route as uncertain ownership instead of silently admitting replacements. Qualification takes production's process lock and requires production to be paused, preventing a trial from adding six requests to four running production requests. Four remains the default.

2. **Avoid model repairs for whitespace.** `presentation-2` standardizes line endings, trailing whitespace, and blank lines after Markdown headings. It retains the prior single surrounding-fence removal. Words, order, Hebrew characters, quotations, citations, substantive validation, and the one-repair limit remain intact. Raw and normalized artifacts plus normalizer/version/violation evidence are retained privately. The content profile and current regeneration epoch remain unchanged.

3. **Replace per-session 500 ms monitoring with shared events.** One authenticated `/global/event` stream routes events only to owned sessions. It is enabled only after checking the installed 1.18.33 schema's permission, message, and part shapes. A healthy connection reconciles every 30 seconds; disconnect or unsupported schemas use a shared two-second polling loop. Reconnect schedules reconciliation for missed tools/permissions. Final complete messages still verify model, High effort, cost, token usage, tool rejection, and completion. Cleanup still aborts, confirms idle, then deletes only owned sessions. First-output timing ignores user-prompt echoes. Concurrent expired runtime checks share one promise.

4. **Correct durable request accounting.** Known successful usage replaces the oversized reservation after completion. Interrupted work keeps its conservative reservation; an active or uncertain request remains charged even after its start ages past a minute. Request starts, active slots, and token accounting remain separate. Both routes, repairs, retries, and observed helpers share the same durable budget. No model output cap, effort reduction, paid fallback, or provider-quota claim was introduced.

5. **Keep quarantine distinct from publishable work.** Rejected notes without an accepted artifact no longer consume a publishable outbox slot. A separate visible 10,000-record / 1 GiB quarantine limit counts retained source, accepted artifact if present, and private attempt evidence. A bounded maintenance audit accounts for pre-update evidence too. Actual free-disk admission still protects the entire filesystem; evidence is not deleted to make space.

6. **Index live recovery state and expose useful measurements.** Partial indexes cover live sessions and requests; another index covers artifact recovery order. The actual baseline query plans used full scans, including a temporary artifact sort. Regression checks require indexed plans. Additive queue-v2 tables record request phases, first-pass results, repair causes, source size/duration, and private evidence bytes. Metrics separate claimed work, live sessions, and observed active provider requests, and show rolling publication rates, token fields, source-hours, ready/publishable ages, memory/disk waits, and event-loop delay. Timing summaries expose outcomes rather than presenting failed requests as successful inference latency.

7. **Make the configured inference deadline effective.** A controlled trial reproduced six-minute transport failures even with the shared monitor. Investigation found that Node's Fetch/Undici transport has an independent five-minute header timeout, while the application allows twenty minutes for complete inference. A deterministic delayed-server reproduction, with that transport limit shortened, returned `server_unavailable` / `UND_ERR_HEADERS_TIMEOUT` before the configured deadline. The same reproduction succeeded after replacing local JSON fetches with bounded `node:http` requests governed by the explicit abort signal. No new dependency was added. Cancellation covers headers and body, response bytes remain bounded, redirects are rejected, authentication stays on owned loopback, and HTTP status/Retry-After survive. Sanitized transport error codes are retained for future diagnosis. The original failures discarded their underlying cause, so this does not prove that every historical `server_unavailable` came from this defect.

## Choices deferred or rejected

### Startup memory reservations (October 16 follow-up)

Read-only log replay found 85 samples with prepared work, fewer than four active sessions, at least 3.5 GiB available, and memory admission waiting. The old coordinator permanently added 512 MiB per active generation to `MemAvailable`, even after the shared server had allocated those sessions. A coordinator regression at the observed 3,659 MiB reproduced two active workers instead of four. This is distinct from genuine low-memory waits: the recent 30-minute baseline also contained samples below the 3 GiB floor, which must continue to block new work.

A 180-second live sample covered 18 requests, including 14 new starts. The shared server's RSS ranged from 550 to 634 MiB; the largest aggregate RSS increase across an observed new request was 64 MiB. This small sample cannot establish a universal memory maximum, but supports retaining a generous 512 MiB startup reserve instead of charging it throughout every request.

Production now requires the 3 GiB floor plus 512 MiB for the prospective job and each existing generation whose current active request has not produced assistant output. That startup evidence is fenced by the current lease and request status; prior attempts and a completed generation cannot release a repair's reserve. Existing allocated memory remains accounted in `MemAvailable`. The first cold start now also requires its own 512 MiB margin. No wall-clock expiry releases a reservation, and an unknown startup retains it. Memory is reread before each claim. Metrics expose `generationMemory` so future waits show the exact threshold. The separate qualification runner retains its older conservative per-occupied-generation reservation; this change does not qualify additional concurrency.

The regression covers warm sessions, simultaneous cold starts, insufficient headroom, old-lease evidence, a repair awaiting its own first output, and a memory drop during admission. Four remains the production concurrency; provider silence and external application memory changes remain independent limits. Live results are retained privately in `STATE/upgrades/memory-admission-*.json`; compare verified publication events separately from reconciled records and report both monotonic elapsed time and wall-clock changes.

Do not run eight- or ten-session trials. Do not add Redis, distributed scheduling, more AI supervisors, extra OpenCode servers, lower reasoning, shortened transcripts, or batched unrelated lectures. Three fetchers and one publisher remain adequate for the observed ready buffer and roughly 128 ms median publication stage.

Do not install an adaptive concurrency controller yet. Variable host headroom and server failures would confound a controller that rewarded short-term notes/hour. Keep four until matched measurements show that six improves useful work without resource, cleanup, provider, or quality deterioration. A short trial is evidence of runtime behavior, not sustained capacity.

Keep conservative prompt-byte and output reservations before dispatch for now. The historical sample had 1,550 completed requests, roughly 23,318 mean input tokens, 3,919 mean visible output tokens, and 4,135 mean reasoning tokens; the sampled maximum output-plus-reasoning was 31,799. That supports investigating smaller reservations, but does not establish that admission was the bottleneck or safely predict every future long lecture. Newly recorded wait reasons and prompt sizes permit calibration without guessing.

Retain synchronous fenced recovery and existing teacher-priority/fairness ordering. Making uncertain cleanup asynchronous requires capacity to stay reserved across creation gaps, process restarts, and recovery failures. No measured recovery stall or dispatch-query bottleneck justified that additional change here. The low-risk live-state indexes address demonstrated scans without changing scheduling semantics.

## Primary-source checks

The installed runtime's saved `/doc` schema is the authority for event parsing. [OpenCode's server documentation](https://opencode.ai/docs/server/) confirms the event-stream interface, but current web documentation alone is insufficient for a pinned runtime.

The [OpenCode 1.18.33 usage implementation](https://github.com/anomalyco/opencode/blob/v1.18.33/packages/opencode/src/session/session.ts#L321) subtracts cache usage from fresh input and reasoning from visible output. Its returned fresh-input, visible-output, reasoning, cache-read, and cache-write fields are therefore additive. Reconciliation uses those fields once each; it does not change model parameters.

[SQLite's partial-index documentation](https://sqlite.org/partialindex.html) supports selecting live rows with an indexed predicate. The tests check the real lookup predicates, rather than extrapolating a synthetic microbenchmark into notes/hour.

[Undici's client documentation](https://github.com/nodejs/undici/blob/main/docs/docs/api/Client.md) documents its independent `300e3` header/body timeout defaults. [Node's HTTP documentation](https://nodejs.org/api/http.html#httprequesturl-options-callback) documents request cancellation through `AbortSignal`. The replacement uses a private agent without an additional socket deadline; the application's explicit deadlines remain authoritative.

## Verification and installation

Six regression checks were first run against the old code and all failed, reproducing formatting-repair waste, retained completed reservations, disappearing old active requests, quarantine/outbox conflation, an unenforced six-worker bound, and full-scan recovery plans. They passed after the changes. Runtime tests additionally cover shared monitoring, owned/unowned permissions, reconnect gaps, UTF-8 and CRLF stream framing, concurrent guard failures, pending creation limits, and uncertain creation acknowledgements. Existing crash, cancellation, lease fencing, lost-publication acknowledgement, backup, credential preservation, and rollout tests remain required.

The isolated four-session trial used twelve frozen complete transcripts from six teachers, ranging from 22,481 to 157,441 raw VTT bytes. Six sources passed structural validation (one required repair), four failed with `server_unavailable`, and the last two were gracefully cancelled during diagnosis. Peak actual concurrency was four; the largest sampled server tree was 777,108 KiB. Host available memory fell to 1,612.6 MiB, despite the server tree staying below 1 GiB. Admissions waited rather than bypassing the reserve. A six-session trial was therefore not justified. No trial note was published, no human review was invented, and production qualification was not increased.

The live shared event stream stayed connected through the 780.97-second trial. It made 23 global permission reads and 70 history reads in total, about 0.12 monitoring reads/second across all sessions. This directly verifies reduced monitoring traffic; it does not establish a notes/hour speedup. The delayed-server reproduction failed after 1,013 ms with a 2,000 ms configured deadline and a healthy 1,500 ms server response; the fixed transport succeeded after 1,512 ms. Evidence remains private under `outputs/notes-throughput`.

The post-fix canary repeated two of the previously failed sources with production paused and a two-session maximum. Both passed on their first response, in 81.726 and 102.416 seconds. The whole run took 108.279 seconds; peak sessions were two and minimum sampled available memory was 5,770 MiB. This confirms working full-source inference and cleanup with the replacement transport, but changes in host/provider conditions prevent treating it as a controlled speedup measurement. No trial output was published.

Validation: 70 pipeline/runtime/publication tests passed; 11 deployment/transcript tests passed and one opt-in live catalog test was skipped. Repository lint, TypeScript, emitted-package installation/reinstallation/rollback tests, and whitespace checks passed. The final recovery regression proves that an unsuccessful reconciliation retains uncertain reservations, while successful cleanup releases finished uncertain callbacks without releasing a newly admitted request awaiting its first session. No sustained speedup or source-fidelity score is inferred from structural acceptance.

The final installed bundle is `1cf77bd71435a0c2f84a6b8f657bcc9da309e9908cd090895f93c9b33a86e877`. The installer independently verified SQLite integrity, preserved all 1,198 completed checkpoints and hashes, and verified unchanged writer credentials. The regeneration epoch remains `1792008157116`; route, qualification, and persistent pools remain server High / four / 3-4-1. Live runtime checks verified the pinned server/schema/configuration and zero prices. The first installed build produced seven new publications; six passed additional independent TiDB readback before the final recovery fix was installed. Production resumed with the same four-session configuration and six-session ceiling. Post-install query plans use the new live-state indexes without the previous artifact sort. Private evidence is `outputs/notes-throughput/installation-verification.json`; the final consistent rollback assets are under `STATE/upgrades/install-20261015T053902-663502`.
